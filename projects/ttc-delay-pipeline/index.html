Architecture

Bronze, Silver, Gold

LayerWhat happens
BronzeFiles are downloaded as published, kept as text, and tagged with source and ingest time.
SilverTypes are cast, station and line names standardized, duplicates dropped, and bad rows sent to a rejects table with a reason.
GoldBusiness-ready tables: daily summary, station ranking, hourly pattern, monthly trend and cause breakdown.
Quality9 automated checks covering nulls, ranges, duplicates, reject rate, unknown-line rate and gold-to-silver reconciliation.
LedgerOne row per source file with its last-modified time and SHA-256, so unchanged files are skipped on the next run.

What the real data taught me

Each problem became a fix and a test

  • The portal publishes the "since 2025" data four times. The ingest keeps one copy per dataset and prefers CSV.
  • The line column has many spellings and a few junk values. They collapse to a small set of clean codes, and blank or other stays under 0.4% of rows.
  • Station names are truncated and carry line qualifiers. About 13,400 rows name a track segment or a whole line, so they are flagged and left out of station rankings.
  • The 2017 to 2021 files are Excel workbooks with one sheet per month. My first loader read only the first sheet, so the warehouse looked as if the City had published almost nothing. The dashboard exposed it.
  • About two thirds of rows have zero delay minutes, so averages are reported next to incident counts.
